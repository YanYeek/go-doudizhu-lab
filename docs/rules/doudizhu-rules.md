# 经典三人斗地主规则与实现规范

> 本文是项目的规则事实来源。公开资料中的斗地主存在大量地区和平台变体；发生差异时，以本文明确写出的“项目裁定”为准，并由测试锁定行为。

## 1. MVP 边界

第一阶段实现经典三人、单副牌斗地主：

- 三名玩家：一名地主，对抗两名农民；
- 一副 54 张牌；
- 叫分确定地主；
- 实现基础牌型、出牌、过牌、胜负和基础计分；
- 不实现抢地主、明牌、加倍、癞子、欢乐玩法、货币系统、匹配评级和 AI。

## 2. 牌与大小

牌由唯一 `ID`、点数 `Rank` 和花色 `Suit` 组成。花色用于区分实体牌和前端显示，不参与牌型识别与大小比较。

点数从大到小：

```text
大王 > 小王 > 2 > A > K > Q > J > 10 > 9 > 8 > 7 > 6 > 5 > 4 > 3
```

大王和小王不能组成对子。

## 3. 开局与叫分

1. 洗混 54 张牌。
2. 每名玩家获得 17 张牌，剩余 3 张为底牌。
3. 随机选择首位叫分玩家。
4. 玩家按固定座位顺序依次选择“不叫”，或叫出高于当前最高分的 `1`、`2`、`3` 分。
5. 有人叫 `3` 分时立即结束叫分；否则一轮结束后，由最高叫分者成为地主。
6. 所有人都不叫时，本局作废并重新洗牌发牌。
7. 地主获得并公开底牌，手牌变为 20 张。

项目不把界面上的顺时针或逆时针当作规则；服务端只根据固定的 `nextSeat` 顺序推进。

## 4. 出牌回合

- 地主首先出牌。
- 获得自由出牌权的玩家可以打出任意合法牌型，但不能过牌。
- 跟牌玩家可以过牌，或打出能够压过上一手牌的牌。
- 普通牌型只有在**牌型相同且牌数相同**时才能比较，比较其主点数。
- 炸弹可以压过任意非炸弹、非火箭牌型；更大的炸弹可以压过较小炸弹。
- 火箭可以压过所有牌型。
- 一手牌打出后，若其余两名玩家连续过牌，则这一轮结束；最后成功出牌者重新获得自由出牌权。

## 5. 合法牌型

| 牌型 | 规则 | 示例 |
|---|---|---|
| 单张 | 任意一张牌 | `A` |
| 对子 | 两张相同点数牌，不含双王 | `77` |
| 三张 | 三张相同点数牌 | `999` |
| 三带一 | 三张加一张单牌 | `666 + K` |
| 三带二 | 三张加一个对子 | `JJJ + 44` |
| 顺子 | 至少五个连续点数，每个一张 | `34567` |
| 连对 | 至少三个连续点数，每个两张 | `334455` |
| 飞机不带翅膀 | 至少两个连续点数，每个三张 | `444555` |
| 飞机带单翅膀 | `n` 个连续三张，加 `n` 张单牌 | `444555 + 7K` |
| 飞机带对翅膀 | `n` 个连续三张，加 `n` 个对子 | `444555 + 77KK` |
| 四带二单 | 四张相同点数，加两张单牌 | `8888 + 4A` |
| 四带二对 | 四张相同点数，加两个对子 | `8888 + 44AA` |
| 炸弹 | 四张相同点数牌 | `QQQQ` |
| 火箭 | 大王和小王 | `小王大王` |

顺子、连对和飞机的连续主体不能包含 `2` 或大小王。

## 6. 项目裁定

斗地主平台之间在“翅膀”和“四带二”等细节上存在差异。为保证代码和测试唯一，本项目采用以下裁定：

- 附带牌不能使用主体三张或四张的点数。
- 附带牌不能包含火箭，也不能把炸弹作为附带牌拆出。
- 飞机的单翅膀允许两张单牌点数相同，但它们不能来自炸弹。
- 四带二单允许两张单牌点数相同，但它们不能来自炸弹。
- 飞机的对翅膀和四带二对必须由互不相同点数的真实对子组成，不能把四张同点数牌当作两个对子。
- 同一组牌可能符合多种解释。识别器必须返回确定的规范结果；在跟牌场景中，可以结合待比较牌型判断是否存在合法解释。

这些裁定属于项目规则，不声称代表所有线下或商业平台。

## 7. 比较规则

规则层先将牌识别为结构化牌型，再进行比较，不能直接比较原始牌数组：

```go
type Pattern struct {
    Type     PatternType
    MainRank Rank
    CardCount int
}
```

- 普通牌型：`Type` 和 `CardCount` 必须相同，再比较 `MainRank`。
- 炸弹：压过普通牌型；炸弹之间比较点数。
- 火箭：始终最大。
- 三带一、三带二、飞机和四带二只比较主体点数，不比较附带牌。

## 8. 胜负与基础计分

- 地主先出完全部手牌，地主获胜。
- 任意农民先出完全部手牌，农民共同获胜。

基础计分在核心玩法稳定后实现：

```text
最终倍数 = 地主叫分 × 2^(炸弹和火箭数量) × 春天系数
```

- 每次炸弹或火箭使倍数翻倍。
- 地主获胜且两名农民从未成功出牌，称为春天，再翻倍。
- 农民获胜且地主只成功打出过开局第一手牌，称为反春天，再翻倍。
- 春天判断统计“成功出牌次数”，不是玩家经历的回合数。

## 9. 服务端权威模型

服务端是唯一规则裁判：

- 客户端只提交意图，例如叫分、出牌的牌 `ID`、过牌。
- 服务端验证轮次、牌所有权、牌型和大小，再改变状态。
- 每张牌必须有唯一 `ID`，出牌时按 `ID` 从手牌移除，避免只按点数导致重复牌错误。
- 其他玩家只能看到公开出牌和剩余牌数，不能收到隐藏手牌。
- 底牌在确定地主前保持隐藏，确定地主后公开。

建议状态机：

```text
WAITING -> DEALING -> BIDDING -> REVEALING_KITTY
        -> PLAYING -> SETTLING -> FINISHED
```

`PLAYING` 至少记录当前座位、最后成功出牌者、上一手牌及牌型、连续过牌人数。

## 10. 最低测试清单

### 牌与发牌

- 牌堆恰好 54 张且每个 `ID` 唯一。
- 三人各 17 张，底牌 3 张；地主获得底牌后为 20 张。

### 牌型识别

- 每种牌型包含正常、最短边界、最长边界和非法案例。
- 顺子、连对、飞机主体拒绝 `2` 和大小王。
- 覆盖重复单翅膀、炸弹不能作为附带牌、多义牌组等项目裁定。

### 牌型比较

- 相同牌型与牌数正常比较。
- 不同牌型或不同牌数不能直接比较。
- 炸弹、火箭及附件不参与主点数比较。

### 对局流程

- 自由出牌时不能过牌。
- 玩家不能打出不属于自己的牌。
- 两人连续过牌后清空上一手牌，并将自由出牌权交给最后成功出牌者。
- 正确判定地主或农民获胜。
- 正确计算炸弹倍数、春天和反春天。
- 不向无权限客户端泄露手牌和未公开底牌。

## 11. 推荐实现顺序

1. `card`：点数、牌、牌堆、洗牌和发牌。
2. `pattern`：牌型识别及表驱动测试。
3. `pattern`：牌型比较及表驱动测试。
4. `game`：手牌所有权和安全移除。
5. `game`：叫分和对局状态机。
6. `game`：出牌、过牌、轮次重置和胜负。
7. due Node 路由与 Go 测试客户端。
8. Cocos Creator 最小联调界面。
9. 基础计分。
10. AI 放到完整联网对局稳定以后。
